# OCR 与通知处理规则

## 截图 OCR

1. 用户通过系统图片选择器主动选择截图，或在其他应用选择分享给本应用。
2. OcrImporter 使用 Core Vision Kit 的本地文字识别接口，保留识别文字与行的位置。超长图片按高度分块识别，并用重叠区域减少行被截断或重复。
3. 导入流程从本机规则设置读取启用的 OCR 规则。OcrSourceDetector 按命中表达式数量选择唯一最高的来源；零命中或并列时交给用户选择。
4. OcrImportCoordinator 将通用规则交给 GenericOcrParser；已保存的旧收据规则仍走 ReceiptParser，工商银行规则仍走 IcbcParser。解析产生草稿，不写数据库。
5. 用户在复核页检查日期、时间、金额、方向、商户和分类，取消不需要的记录后再保存。

图片在导入流程结束后释放图像资源，不作为账本附件保存在应用数据库。识别文字保留在当前复核流程中供用户检查，不上传服务端。

### OCR 识别规则

在“账本”页签的设置中可打开 OCR 识别规则。首次初始化的微信和支付宝规则使用通用视觉行模式，工商银行继续使用兼容解析器。用户可新增来源、设置来源显示名称、编辑规则、启停、调整顺序或删除规则。来源标识会写到账目来源字段；显示名称用于复核界面。

通用规则可选择两种记录模式：视觉行模式将同一横向位置的 OCR 文字聚合成行，并以含金额的行为交易候选；起始锚点模式从匹配的交易起始行开始，持续到下一起始行。金额、日期、方向、商户和分类表达式中的第一个捕获组是字段值；需要给字段限列时，left/right 使用图片宽度归一化后的 0 到 1 横坐标。列范围要求图片宽度，缺失时不会退回到整页文字匹配。

来源匹配不再配置权重、最低分或分差。多个匹配表达式按命中数量计分；零匹配或来源并列时要求用户手动选择。确定来源后，解析流程按列表顺序尝试该来源的启用规则。规则保存在设备本地的 ArkData Preferences，OCR 规则从旧版迁移到版本 2，不改动账本数据库结构。

规则页提供“复制 OCR 提示词”和 JSON 输入框。用户可将提示词及自行选择的 OCR 样例交给外部 AI，再粘贴生成结果；应用不会调用 AI 或上传样例。有效 JSON 会由本地 OCR 解析器试跑。输入样例是纯文字，因此预览不会核实视觉列范围；保存前应使用真实截图复核。预览样例只保留在当前设置页面状态，不写入 Preferences；用户点“确认保存导入规则”后才保存运行时规则。

## 日期、金额与例外

- 只有存在可信日期，才会生成可入账草稿。缺少日期或无法合理解析的项目会跳过，不用截图导入日补造日期。
- OCR 只识别到日期而没有时分时，草稿会标记 has_time=false；不会合成 12:00 或其他默认时刻。
- 工行截图中的“周一/周四”等日期标题，结合截图时间及其前 7 天窗口求得对应日；超出窗口或月份冲突时不猜测。
- 金额作为人民币整数分写入数据库。
- 初始规则会过滤已关闭、失败、撤销等交易；退款方向不明确时需要用户核实，过滤行为可在规则设置中调整。
- 草稿分类由当前 OCR 规则中的分类表达式和分类映射决定；无匹配时使用规则配置的默认分类。商户使用 OCR 识别到的交易文字，并允许用户在复核时修改。
- 解析阶段按来源、同日、金额和商户生成相似重复提醒。保存阶段仅对带可靠时分的交易，将时间戳、金额和方向完全相同的已有账目或当前草稿合并，不新增条目；如草稿有明确分类，会更新匹配账目的分类。只有日期、没有时分的记录不会按此规则自动合并。用户最终确认后才写入。

## 通知自动入账

需要用户在系统设置中授权通知访问，并选择要转发的通知来源。首次初始化的通知规则覆盖工商银行、中信银行、支付宝和微信支付；只有匹配启用规则且能解析出有效金额、收支方向和时间的通知才会自动入账。失败、撤销等规则排除的内容不会写入账本。

### 通知识别规则

在“通知”页签的通知设置中打开“自动入账识别规则”，可新增、编辑、启停、排序和删除规则。新规则使用语义命名捕获：正文正则必须包括 `(?<amount>...)` 和 `(?<direction>...)`，日期策略不是投递时间时还需 `(?<date>...)`；`merchant` 和 `category` 可选。结构括号用 `(?:...)`。方向字段仍需与收入/支出关键词完全一致。旧版规则保留原数字捕获映射，继续按兼容路径解析。

通知规则页也提供“复制通知提示词”、JSON 粘贴、本地校验、样例预览和明确保存。通知预览调用正式 NotificationRuleEngine，但不会归档样例通知或自动记账。样例和预览结果不写入 Preferences。规则存储从版本 1 迁移到版本 2；旧正则、数字捕获和规则顺序原样保留。

通知历史本身是“通知”页签的主页面，和“账本”页签同级；进入通知设置后可返回通知历史。通知设置页不再重复提供“查看通知历史”入口。

支付宝和微信支付的初始规则分别用标题/来源和正文中的方向关键词、金额共同判断。公开资料没有定义覆盖所有通知类型的固定正文模板，因此默认表达式只覆盖已配置的通知格式，用户可按实际收到的通知调整规则。缺少可解析金额或方向时不会入账；默认商户为平台名，默认分类为“其他”，失败、撤销和退款内容会被排除。自定义规则的行为取决于用户配置。

旧版已保存的银行默认规则会一次性补入支付宝和微信支付默认项，同时保留已有配置。已经保存的空规则集或仅有自定义规则的集合不会被默认项覆盖。设置页保存的删除状态会保留。

参考资料：[微信支付二维码收款产品说明](https://pay.wechatpay.cn/doc/v3/merchant/4012154495)、[支付宝到账提醒排查说明](https://consumer.huawei.com/cn/support/content/zh-cn00410681/)。

NotificationProbeExtension 对每条收到的通知独立启动以下路径。自动记账路径读取当前规则，并通过 BankNotificationParser 将系统通知转换为通用输入，再由 NotificationRuleEngine 执行规则匹配：

- 归档：记录来源应用、标题、正文、系统发布时间和本机接收时间，供通知历史页按来源、关键词和日期查询。通知详情中的文字可选择和复制。
- 自动记账：规则匹配后解析来源、商户、方向、金额和交易时间，再写入账本。识别为收入或支出后仍以正数分保存。归档路径或记账路径失败只影响各自工作，不阻断另一条路径。

通知自动记账用方向、金额和交易分钟在已有账目中查重。若找到同笔记录，不增加条目；如果原分类为“其他”且通知提供明确分类，只更新原记录分类。新记录会发出账目变化事件，由首页重新加载本地账目。

修改规则只影响之后处理的通知，不会重新解析通知历史或修改已有账目。

通知接收需要 SUBSCRIBE_NOTIFICATION 权限。穿戴设备通知转发可另外申请 ACCESS_BLUETOOTH。截图通过系统选择器选择，不请求对图库的广泛读取权限。

## 精度与使用限制

OCR 可能把金额符号、负号、日期或商户文字识错；支付应用界面和通知模板也可能更改。任何截图草稿都应先复核；新通知模板要结合本地诊断信息核对。通知归档保存完整标题和正文，因此可能含个人或金融信息；数据库保持在设备本机。
