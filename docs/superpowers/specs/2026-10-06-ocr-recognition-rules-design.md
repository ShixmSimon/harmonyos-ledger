# OCR 识别规则设计

## 目标

将 `notificationRules` 中的模型、引擎和金额解析器从 `.ts` 改为 `.ets`，并为截图 OCR 增加独立、可在应用内编辑并保存在本机的识别规则。通知规则和 OCR 规则各自处理不同输入，避免将通知正文规则直接套用到带坐标的截图文字。

## 已确认的范围

- OCR 规则覆盖当前支持的微信支付、支付宝和工商银行截图来源。
- 每个 OCR 规则可编辑来源识别条件、日期、时间、金额、方向、商户和分类等字段匹配，以及失败、退款和汇总内容的过滤条件。
- 规则可在应用中新增、编辑、启停、排序和删除，并使用独立于通知规则的本机 Preferences 存储。
- 默认规则沿用当前三个来源的识别结果和账目字段行为。
- 图片文字识别、行坐标、分块识别、账目数据库结构和复核后保存流程保持原有边界；截图解析只生成草稿，不直接写入账本。

## 方案

### 通知规则模块

将 `AmountParser.ts`、`NotificationRuleModels.ts` 和 `NotificationRuleEngine.ts` 改为 `.ets`，把引擎中的显式 `.ts` 导入改为项目现有 `.ets` 导入习惯。保留规则结构、匹配顺序、默认规则和已保存通知规则格式，不改变通知识别行为。

### OCR 规则模型与执行

新增独立的 OCR 规则模型、引擎和存储服务。每条规则包含稳定 ID、名称、启用状态、账目来源和布局策略。来源识别由加权表达式列表、最低分和来源分差阈值组成，以保留当前的评分语义并允许用户修改。字段匹配包含金额、日期、时间、方向、商户和分类表达式及其 1 起始的捕获组编号；分类映射、收入/支出关键词、失败/退款/汇总过滤表达式和日期格式也可编辑。金额表达式提取原始金额文字后仍交给金额解析器校验，日期表达式得到的文本仍须通过日期校验。

布局策略限于现有两类：账单列表（微信/支付宝）和银行明细（工行）。规则表达式负责描述可变的文字模板；布局策略继续负责按 `OcrLine` 坐标聚行、归属相邻日期/商户文字和维护日期上下文。字段表达式在布局策略构造出的交易行或交易块上下文中运行，不对丢失坐标的整页拼接文字直接抽取商户与金额。

OCR 引擎按已启用规则的加权表达式评估整页文本来识别来源；最高分未达到阈值或与次高分的差值不足时，仍进入现有手动选来源流程。确定来源后，引擎将该来源的规则传给其布局策略，由策略读取带坐标的 OCR 行并生成草稿。用户新增的同来源规则按界面顺序尝试，选取第一个产生至少一条有效交易的规则，不合并多个规则的结果。手动选来源时只尝试该来源的规则。规则排序因此决定多个同来源模板的优先级。

金额和日期仍由共享格式化/解析逻辑校验。没有可靠日期的项目不生成可入账草稿；失败或已取消交易被跳过；退款仍要求用户确定方向；无匹配或字段不足的截图继续留在复核流程中供用户检查。

### 编辑界面与保存

在设置中增加 OCR 识别规则入口，界面沿用通知规则页的规则列表与编辑表单模式。编辑表单展示布局策略、带权重的来源表达式与阈值、字段表达式、日期格式、方向关键词、默认分类、分类映射和捕获组编号。保存前验证每个正则有效、每个引用的捕获组存在、分值/阈值有效且来源和布局策略必填。OCR 规则使用独立 Preferences 名称和版本字段。

首次没有已保存配置时写入内置默认规则。已保存的编辑、停用、排序、删除及空规则集均按用户选择保留，不因后续安装或规则版本变化静默覆盖。

### 接入范围

自动来源检测、手动选择来源、系统图片选择器导入和分享图片导入共用 OCR 规则引擎。现有复核、相似重复提醒和保存确认逻辑继续由 `OcrImportCoordinator` 与页面流程负责。数据表、来源枚举和账目字段不变；新增账目仍必须通过复核确认。

## 验收条件

1. 原有通知默认规则、通知自定义规则的载入和保存行为保持不变，相关源文件全部使用 `.ets`。
2. 微信、支付宝和工行三种默认 OCR 规则能识别现有支持的布局，并保留原有日期、时分、方向、商户、分类、退款和失败交易处理行为。
3. OCR 规则编辑、启停、排序、删除和空规则集状态可持久化；表达式错误或捕获组无效时不能保存。
4. 图片导入和分享导入都使用已保存的 OCR 规则；来源不明确时仍可人工选择来源。
5. OCR 仍仅产生待复核草稿，不修改数据库，且没有数据库结构迁移。

## 验证

- 检查项目构建与 `git diff --check`。
- 在可用的 HarmonyOS 7 / API 26 设备上核对三类默认截图、手动来源选择、规则编辑保存以及复核入账流程。
- 设备不可用时，在交付说明中注明未完成设备核对。

## 风险与边界

- OCR 文字识别可能误读文本；可编辑规则只能改变模板匹配，不能修复系统 OCR 的错误识别。所有草稿仍需用户复核。
- 带坐标的列表与银行明细在交易归属方式上不同，不能仅靠一条跨来源通用正则安全替代现有布局策略。
- 规则配置仅支持现有三个账目来源；增加新的来源或不同的布局策略需要另外扩展来源类型、布局解析器和复核文案。
